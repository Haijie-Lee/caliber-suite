# plan-drafting

全级 plan 起草引擎。调用点 = caliber MS 级阶段 2 直调（轻量档）与 plan-forge
工序 2（ML/L 完整档）；MS 级输入 = 阶段 1 方案确认记录，ML/L 级输入 = CONTEXT
+ plan-forge 工序 1 选材产物。
> 变更日志归工作仓 `docs/skills-changelog.md`（skill 文件不携带 changelog——2026-09-25 用户裁定：log 只记工作仓，不进发布仓）。

## 为什么有效

- **逐字执行者读者**：plan 的唯一契约读者是不看其他任何文档、逐字执行的较弱
  执行者——每条指令必须就地自足，plan 里的 bug 会原样变成代码 bug。
- **未测量值不进 plan**：版本号、计数、路径、原文片段先实测再写入——想象的
  事实是执行期炸弹。
- **契约先于实现**：跨任务契约（签名/格式/常量/枚举）动笔前先列表钉死，各任务
  Interfaces 块与矩阵逐字一致。
- **模板与验收同炉**：起草者最知道 reviewer 查什么——验证期望与模板同炉锻造，
  不是写完后补一句「验证它正确」。

## 何时使用 / 不使用

- 用：MS/ML/L 级计划起草（MS = 轻量档直调；ML/L = 完整档，经 plan-forge
  工序 2 编排调用）。
- 不用：S 级（无 plan 文档，对话内解决）；对抗审查归 plan-review-ritual 与
  plan-forge 工序 3-4——本 skill 只做起草与自查。

## 输入

- `CONTEXT`：澄清产物（L 级 = deep-probe 对齐快照；MS/ML 级 = 阶段 1 方案确认
  记录）。
- `LEVEL`：`MS` / `ML` / `L`（任务分级归 caliber Step 1，本 skill 不重复分类）。
- `ENGINE_PATH`：`coding-forge` / `exec-forge` / `inline`（MS 恒 inline）。
- `选材产物`：ML/L 级经 plan-forge 工序 1 的选材输出（适用契约、陷阱、
  checklist 节）。
- 输出路径：MS = `.caliber/plans/YYYY-MM-DD-<slug>.md`；ML/L =
  `docs/plans/YYYY-MM-DD-<主题>-plan.md`。

## 模板分档

道层条款「MS/ML/L 三档模板」据此实现。

### MS 轻量档

≤1 页。五节（逐条一行列出）：

①目标+成功判据
②文件清单+每文件改法（关键代码）
③验证命令+逐字期望输出
④commit 划分
⑤风险（可空，仅不可逆/共享路径）

落盘 `.caliber/plans/YYYY-MM-DD-<slug>.md`。`.caliber/` 首次创建时：项目根
存在 `.git` 目录且 `.gitignore` 无 `.caliber/` 行 → 追加一行 `.caliber/`；
无 `.git` → 跳过并输出一行说明（与 caliber Step 1.5 第 4 步同规则）。

注：fallback §简plan 为本档兜底简版（plan-drafting 缺席时 caliber 读
fallback.md）。

### ML 标准档 / L 完整档

两档分列命名、节序相同，唯一差异 = 对齐快照节填入源：ML 级以阶段 1 方案确认
记录填入、L 级由 deep-probe 产物填入。共同节序（模板节名逐条一行纯文本列出）：

对齐快照节（五段：目标重推 / 道层条款（价值排序/不可妥协项/失败的形状）/ 开放决策点+方案选定记录 / 挂起项（带触发器）/ 前提清单）
Global Constraints
Review Focus（≤5 条，空节 = 「查过且没有」）
契约矩阵
任务块（画像/步骤/Interfaces/验证期望）
执行编排预分配表（exec-forge 路径必产、coding-forge 路径免产）
风险登记
技能消费裁定节占位

## 六道锻造

原生工序（自 plan-forge 工序 2 下沉；plan-forge 侧保留选材/锻打/准出/成型
四道编排职责）：

1. **契约矩阵先行。** 动笔写任务前先列跨任务契约表：函数签名（参数/返回
   类型）、dataclass 字段（新增字段带默认值放末尾，否则已有构造全部
   TypeError）、消息/文件格式、常量名。每个任务的 Interfaces 块
   （Consumes/Produces）与矩阵逐字一致。
2. **判断前置扫描。** 初稿完成后全文扫描判断逃逸词：
   `适当|视情况|必要时|类似|照做|合理|尽量|等等|按需|妥善处理`；英文等价物
   同样命中：appropriate / as needed / similar to / handle properly。
   每处命中 = 留给执行者的即兴空间，展开成具体指令（做什么、做到什么
   程度、怎么算做完）；展开不了的转显式问题进风险登记。
3. **验证内建。** 每个验证步骤给具体期望输出（数字算到个位数、字符串逐
   字），不是"验证它正确"。
4. **风险登记。** plan 末尾风险表：每条 = 触发条件 + 爆炸半径 + 可逆性 +
   处置（修/兜底/接受）；延期决策必带重访触发器。
5. **任务画像标注。** 逐任务标画像，供 caliber 阶段 4 §动态组合 消费。
   格式定死：`画像: 性质=…; 难度=…; 领域词=[…]`。性质（新增/修bug/重构/
   原型/配置/文档/调研/操作）、难度（机械/集成/判断）、领域词（供路由表
   关键词匹配）。**只标画像、不锁 skill 组合**——起草时执行信息未齐，锁定
   发生在工序 4 彩排后的预绑定回写。画像缺失 → caliber 按"集成"对待。
6. **执行编排预分配**（非 coding 主导或无 git 的 ML/L plan 必产；coding 主导
   plan 免产——coding-forge 自带角色分配）。逐任务填执行编排预分配表。
   **只预分配、不锁死**——dispatch 边界可据运行时信息微调，微调记
   ledger Ruling；阶段 4 入口批量确认停止点（caliber）确认的是本表。
   默认规则（plan 未预分配时）：判断类/组合复杂 → inline + 独立审查；
   机械 → dispatch + 独立审查；集成 → dispatch + 注入。
   schema 块：

### 执行编排预分配表（schema——caliber 引擎契约，plan-drafting 与 exec-forge 两处逐字一致）

| 任务 | 性质 | 难度 | 形态 | 执行者 | 审查者 | 注入档 | 领域组件 |
|---|---|---|---|---|---|---|---|

- **形态**：`inline`（主线程执行）/ `dispatch`（subagent 执行）。
- 枚举外行（如 用户协作，用于冒烟/发布决策等人工任务）：引擎不派工、不进审查门，仅在 ledger 记一行。
- **执行者**：dispatch 时 = agent_type 链（caliber §动态组合 2b 映射表，
  去前缀匹配取首个在场者，全缺席退 general-purpose）；inline 时 = 主线程。
- **审查者**：任何形态都 **≠ 执行者上下文**；inline 任务完成后必派独立
  reviewer（制度化补审门，防 controller 自审跳过）；席位 = `caliber:exec-reviewer`（缺席退 general-purpose，2b 链）。
- **注入档**：`指令化` / `许可清单` / `无`（决策见 §任务环 step 2 ③；
  ledger 组合行对 inline 任务记 N/A——主线程无需注入档）。
- **领域组件**：路由表命中（候选）；plan-forge ≥1.5.0 工序 4 彩排后经编排者
  裁定回写为**预绑定**（1.4.0；与 exec-forge §输入、caliber §动态组合 同源逐字：
  预绑定 = 默认消费——dispatch 边界偏离须记 ledger Ruling，终审闭环核查）；
  未经彩排的 plan 保持候选非绑定旧语义（组合决定由编排层在 dispatch 边界
  做出）。

注：本块内 `§任务环` 等无限定节名指 exec-forge/SKILL.md 内部节（schema 与
exec-forge §输入节逐字一致，两处同步为引擎契约）。

## 自查清单

初稿完成后逐条过，每条发现必须引用原文；零发现项也要留"查了什么"一句。

### 判断逃逸词扫描
- [ ] 全文搜 `适当|视情况|必要时|类似|照做|合理|尽量|等等|按需|妥善处理`——
      每处命中展开为具体指令（做什么/做到什么程度/怎么算做完）或转显式问题
- [ ] 英文等价物同样命中：appropriate / as needed / similar to / handle properly

### 契约矩阵
- [ ] 每个跨任务函数：签名（参数名/类型/返回）在 Consumes 与 Produces 逐字一致
- [ ] dataclass 新增字段：带默认值且放末尾（否则已有构造 TypeError 或静默错绑）
- [ ] 同一函数/字段/常量在任何两个任务里拼写完全一致（含大小写）
- [ ] 正文引用的每个类型/函数/常量/文件，都能在矩阵或某任务中找到定义点

### 验证内建
- [ ] 每条测试断言的期望值：把输入代入实现心算一遍，与断言一致
- [ ] 每个"运行命令验证"步骤：期望输出具体到可比对（不是"应该成功"）
- [ ] fixture 数据来源标注（真实样本路径 / 抓取日期）
- [ ] **残留/存在性检查正则的反身自伤**（实证：2026-08-13 文档整合——`(doc|plans|reference)/` 模式命中迁移后的合法新路径 `docs/plans/`、`../plans/`、树行 `├── plans/`，4 条验收命令在完美执行下全部误报"残留"）：设计验证时先枚举**合法新内容**的形态（前缀 s、前缀 /、树行、表行、白名单行），用前导字符排除（`[^A-Za-z0-9s/]`）+ 白名单行号显式列出；新写入的文档内容尽量用全名（`docs/plans/` 而非 `plans/`）减少白名单
- [ ] **计数验证命令的尾换行陷阱**（实证：`printf '%s' "$G1" | wc -l` 吞掉尾换行——非零残留显示为 0，假绿）：用 `printf '%s\n'`；"0 行"期望必须能证明是真 0，不是公式吞了输出
- [ ] **禁忌/红线词表的规则定义自嵌**（实证：2026-09-16 file-hygiene T9 F-1——AGENTS.md 纪律行逐字内嵌五词禁忌表，仓级禁忌 grep 对该文件永久假阳性、词表随每会话注入）：定义「禁出现词 X」类规则时，规则文本用指针式（词表见 <单一权威件>），词表逐字只存在于唯一权威位置；验证 grep 扫描范围只含被约束产物目录，不含规则定义件
- [ ] **写入清单 ↔ 验证锚一一对应**（实证：2026-09-23 trans-forge plan T9——M10 四件落盘清单，任务验证节四锚只覆盖建图一件，双产物从未落盘而四锚全绿，终审 F-A 抓出）：plan 每声明一件「写入/落盘」类交付物，验证节必配一条「该路径存在 + 关键属性实测」（`test -f` / `wc -l` / 计数命令）的锚；验证锚不得能由中间产物（草稿/隐藏件）满足——锚从交付物清单派生，不是另写一套
- [ ] **条件-动作对的动作分支有独立验证锚**（同源实证）：「X 过 → 做 Y」型停点/门，动作分支 Y（落盘/迁移/上报）必须有自身验证命令——只验条件 X 时，Y 的缺失在全部锚绿下不可见

### 风险登记
- [ ] 每条风险四要素齐全：触发条件 / 爆炸半径 / 可逆性 / 处置
- [ ] 延期决策带重访触发器（"出现 X 时回来定"）
- [ ] 不可逆操作（删数据、外发、硬件写入、force push）有显式停止点
- [ ] **验证命令的扫描范围是否包含 plan/spec 文件自身**（实证：plan 的替换表"旧字符串"列含旧路径，全局残留 grep 把 plan 文件打成残留；graphify 生成索引、URL 路径段同理）——已知例外清单必须显式列入 plan/spec 文件名，且 grep 按文件名前缀过滤

### 任务画像标注
- [ ] 每任务画像三要素齐全：性质（新增/修bug/重构/原型/配置/文档/调研/操作）、难度
      （机械/集成/判断）、领域词
- [ ] 格式与 `画像: 性质=…; 难度=…; 领域词=[…]` 逐字一致
- [ ] 画像只记性质/难度/领域词，未记 skill 组合决定（锁定发生在彩排后的预绑定回写）

### 任务粒度判据（2026-09-19）
- [ ] 粒度 = 一个行为单元：一个测试能描述完、一个 commit 装得下
- [ ] 坏粒度对照：太大（「实现用户系统」级 → 拆到「校验邮箱格式返回错误码」级）；太小（「加一个 import」级 → 并入所属行为单元）
- [ ] 每个任务块必须有可独立验证的完成判据（验证命令 + 期望输出）

### Review Focus 节（2026-09-19）
- [ ] plan 头部 Global Constraints 后必含 Review Focus 节：spec 隐含但无任务验证覆盖的输入类/失效模式 ≤5 条（最可能伤真实用户者在前），各钉一条验证入所属任务
- [ ] 空节合法但语义 = 「查过且没有」，禁以空节代检查

## MS 审查对接节

MS 级 plan 的审查 = 两道：快速自查五条 + plan-reviewer 单派遣独立审查。

### 快速自查五条（作者本人，ritual Step 1 五条 MS 版）

1. **心算断言**：把每条验证期望的输入代入实现心算一遍，与断言一致。
2. **模块级语句**：regex、常量等模块级语句 import 时就执行——它会炸吗。
3. **跨任务签名一致性**：任务间引用的签名/字段/命名逐字对。
4. **自约束对照**：plan 开头写的每条约束，去正文里找违反点。
5. **平台事实核查**：目标平台的真实行为，不是想象的行为。

每条"没发现问题"必须附"查了什么、为什么没有"一句。

### plan-reviewer 单派遣 prompt 骨架

输入 = MS plan 文件路径；单轮、无收敛循环；发现回写 plan 本文件。

```
你是对抗性 plan 审查员。审查对象 = {MS_PLAN_PATH}（MS 级轻量 plan）。
逐条核查（轻量版）：
1. 字面可执行性：每条编辑/命令指令照字面执行会怎样？锚定串在目标文件
   实存且唯一吗？
2. 仓库交叉核对：plan 引用的路径/版本/计数/原文片段与仓库实文对照。
3. 验证期望具体性：每条期望具体到可机械判定（exact count / exact
   string）吗？
裁定纪律（三级）：Mechanical（事实性错误）→ 直接修复并留痕；
Taste / User Challenge → **停**，上报用户裁定，不自动定。
只报运行时会炸或产物会错的问题；零发现是合法结论（逐项留「查了什么」
一句）。
```

派遣 `Task(subagent_type=plan-reviewer)`，缺席退 general-purpose（本 prompt
全文作注入清单）。

## 交接节
